## 0. 一句话目标

在**不改变现有 Java 后端、数据库、认证 API 和学习业务流程**的前提下，把 RentWise 现有单独登录页升级成 Apple-inspired Modern Minimalism 风格的**品牌展示＋住宅科普＋账号登录**一体化落地页，并建立可供后续 Explore、Living Picks、Risk Coach 页面复用的基础视觉规范。

**这不是重新开发一个房源交易平台。** 本轮不做真实房源检索、不做地图、不做世界建筑图鉴、不做购物车/支付、不做风险情境模拟、不做后台。

## 2. 产品定位与原则

- 网站定位：**租房风险实战学习 + 公开居住文化探索**。本轮上线的是登录落地页与静态住宅知识入口，不是假定存在房源挂牌。
- 视觉核心：Apple-inspired Modern Minimalism（借鉴精致、克制、连贯的体验原则，不复制 Apple 的品牌元素、官网布局素材或受保护视觉资产）。
- 主色：暖白／近白／浅灰／石墨黑；低饱和暖沙色可作少量点缀。正文可读、对比度可靠。
- 图片：**真实、有合法使用权的高品质建筑/室内摄影**，非之前已否决的绿色插画首页方案。
- 交互：自然、简短、有反馈；装饰特效服从可用性，轻微玻璃效果只用于浮动控制、局部导航/遮罩，不做全站玻璃卡片。
- 内容真实性：介绍住宅类型的短文案是**一般性科普**，不能虚构住宅售价、开发商授权、明星住址、可购买或可出租房源。

## 3. UI 0.1 交付范围

### 3.1 Public Login / Landing（优先修改原 `Login.vue`）

**页面组成：**

1. **顶部轻量导航**：RentWise 品牌；「居住知识」「风险学习」等真实可用的导航（尚未开发的功能只能标记“即将推出”或不展示，不允许死链）；右侧登录/注册入口。
2. **首屏统一视觉矩形**：左侧约 58–62% 住宅摄影与动态科普，右侧约 38–42% 当前登录表单；桌面呈一个整体且留白充足。可在视觉上分栏，但不能像两张互不相关的独立卡片。
3. **左侧住宅 Showcase**：3–4 个经过审阅的住宅类型介绍项；图片、标题、短句、当前序号、前后切换／小圆点，点击「了解更多」打开对应科普详情。内容可选普通公寓、长租公寓、LOFT／复式、院落／独栋；不同分类名称可能有重叠，应避免把它们宣称为互斥的法律分类。
4. **右侧登录**：继续使用用户现有账号密码、校验、加载状态、错误提示、注册跳转；保留现有 Pinia 认证行为，不能做一个看起来能登录却不实际调用 API 的演示表单。
5. **首屏下方内容区**：轻柔浅灰或白底的 2–3 个编辑式内容区块（如「住宅选择的三个问题」「签约前注意什么」「不同居住空间」）。避免大量重复的卡片网格。提供有意义的文案，不虚构官方统计或房源数据。
6. **页脚**：轻量品牌说明与教育用途边界，避免声称提供法律意见或真实房源服务。

**响应式**：
- ≥1024px：左右双栏合体；主体宽度适当约束，首屏图像优先。
- 768–1023px：留白/文字缩小，必要时转换为分段上下排列。
- ≤767px：单列；图片在上、登录紧随其后；不能让轮播或装饰区域挤掉登录表单，输入框和主按钮需便于触摸。
- 避免水平滚动、图片文字遮挡和固定高度造成溢出。最终尺寸以实测微调，而非机械照搬断点数字。

### 3.2 住宅科普详情

优先采用**可复用的 Dialog/Drawer 或渐进展开详情**；无需开发复杂的独立房源详情路由。每项包含：标题、代表性摄影、简短介绍、常见优点、可能的不足、签约/入住前可核对的事项。点击、ESC、关闭按钮及焦点回退可用；手机端不依赖悬浮。

### 3.3 最小 Design System

建议按当前工程实际结构建立或整理（具体命名可调整）：

```text
frontend/src/
├── styles/
│   ├── tokens.css             # 颜色/字体/间距/圆角/阴影/动效变量
│   └── global.css             # 基础重置与全局布局
├── components/
│   ├── ui/                    # 基础可复用控件（只抽象真正复用项）
│   └── housing/               # 住宅展示与详情组件
├── data/
│   └── housingShowcase.ts     # 可审核、可替换的静态科普数据
└── views/auth/Login.vue      # 一体化品牌/登录落地页
```

全局规范建议（可微调）：

| 项目 | 目标值/原则 |
| --- | --- |
| 页面背景 | `#F5F5F7` 或相近近白中性色 |
| 正文字体 | 系统 UI 字体栈 + 中文系统回退 |
| 主文字 | `#1D1D1F` 左右的深灰 |
| 辅助文字 | 中灰，确保对比度 |
| 强调色 | 低饱和暖沙色，少量使用 |
| 主按钮 | 近黑实心，清晰 Hover/Focus/Disabled/Loading |
| 圆角 | 依据尺寸分级，不让全站都是大圆角 |
| 交互过渡 | 普通 150–250ms；主要区域约 250–400ms，按实测调整 |
| 栅格 | 统一容器宽度与 8px 间距节奏 |
| 毛玻璃 | 仅用于少数控件，不影响可读性/性能 |

优先适配现有 Element Plus 表单，不为视觉效果引入大型新 UI 依赖。

## 4. 交互要求

- 科普轮播可手动切换。若启用自动轮播，建议约 6–8 秒/次；用户悬浮、聚焦、打开详情时暂停，关闭后合理恢复；尊重 `prefers-reduced-motion`，必要时完全禁用自动切换。切换不得移动登录区域、重置用户名密码或触发页面跳动。
- 轮播前后按钮、序号、活动状态可感知；键盘可操作，不仅通过图片 Hover 提示入口。
- 详情弹层具备明确的关闭按钮、ESC 关闭、焦点管理与返回原触发点。
- 登录表单支持 Enter、空字段验证、请求中的禁用/Loading、密码可见切换、后端错误提醒，登录成功仍去 `/dashboard`。
- 注册仍能从现有 `/register` 进入；已有 token 的用户进入登录页时，现有路由保护逻辑不得倒退。
- 不额外泄露 JWT，不把 token 放进 URL，不改变 `sessionStorage` 的原有策略。
- 图片提供 `alt`、适当尺寸、预加载首屏所需资源，其余按需加载；图片缺失时保留可读替代内容。
- 尊重 `prefers-reduced-motion`；不得只靠颜色/动画传递关键状态；保证可见键盘焦点与文本对比度。

## 5. 图片与内容来源约束

1. 图片必须具备可记录的来源和使用权。禁止直接把搜索引擎图片或未经授权的房产营销图拷到仓库。
2. 允许在开发初期使用**明确标为占位的中性占位素材**，但不得在验收报告里将占位图称为最终实景摄影。图片缺失时通过稳健布局优雅降级。
3. 保存可审查的图片出处/授权记录（例如 `docs/design/assets-attribution.md`）；不要硬编码失效风险高的第三方临时图片 URL。
4. 页面不展示“真实可租房源”、价格、明星私宅或没有出处的官方推广资料。
5. 内容保持简短、准确；不要编造定量比较或地方性法律断言。

## 6. 本轮明确不做

- 中国城市地图、世界地理建筑地图、地形引擎或地图数据维护。
- Living Picks 场景商品热点与外部购买跳转。
- 房源搜索/挂牌/交易、收藏、支付、订单、商家后台。
- 风险决策模拟 F07 业务实现；不调整诊断题库、Profile、Plan。
- Java 微服务、Gateway、Nacos、JWT 签发或 MySQL 的任何改动。
- 不添加用户未经确认的业务 API，不使用虚假数据冒充已上线内容。

## 7. 实施流程（Codex）

**Phase 0｜审计**：确认 Git 状态、分支和 3 项关键认证文件；核实现有 CSS 实际导入情况；列出即将改动的路径以及可能冲突。

**Phase 1｜设计基础**：建立 tokens/global、图片资源规范、少量复用组件；可先制作静态样式，但保留真实登录机制。

**Phase 2｜登录落地页**：实现首屏双栏整体矩形，左住宅摄影/科普，右原有真实认证；继续保留注册和 Dashboard 路由行为。

**Phase 3｜交互完善**：住宅科普详情、手动轮播、必要自动轮播、下方详情区、响应式与键盘操作。

**Phase 4｜回归与文档**：测试、截图/录屏（如本地工具具备）、更新 `docs/design/` 相关文档、`docs/README.md` 和必要的 `CHANGELOG.md`。新文档应注明本轮实现/待办边界。

**工作分支**：只在可确认的 v0.4 开发基线之上建立 `feat/ui-design-system-home`；不要把刚才的文档治理分支作为长期业务开发基线。保持小范围差异，代码与文档同 PR 验收即可。
