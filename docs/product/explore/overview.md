# RentWise Explore｜产品构想与 UI/UX 初步规划

> **版本**：v0.1 · 创意记录稿
> **记录日期**：2026-11-13
> **状态**：产品讨论基线（尚未进入开发验收）
> **适用范围**：RentWise 公开内容探索、首页改版与原有风险学习业务的衔接
> **设计基线**：《RentWise UI/UX 设计规范与页面方案》v1.0

## 01. 一句话定位

**以居住为主题的可交互地理与建筑文化图鉴，用真实、可核实的故事激发探索兴趣，并在适当场景下连接 RentWise 的租房风险实战训练。**

RentWise 的长期体验由三个相互关联、但职责不同的部分组成：

- **China Living Atlas｜中国城市居住图鉴**：探索城市的地理、气候、居住方式及代表性住宅。
- **World Living Atlas｜世界居住文化图鉴**：探索七大洲不同地区的居住建筑，理解建筑与环境、历史、文化的关系。
- **Risk Coach｜租房风险实战教练**：沿用已有诊断、能力画像、自适应训练与阶段测评，并逐步建设情境决策模拟。

**关键边界**：Explore 是文化与居住认知内容模块，**不是房源搜索地图，也不是房源交易平台**。真实房源检索、筛选、交易与管理后台不属于本轮已确认范围。

## 02. 已确认的设计决策

| 主题 | 已确认方向 |
| --- | --- |
| 视觉风格 | Apple-inspired Modern Minimalism；真实高品质摄影、舒适留白、清晰视觉层级、适度动效与局部玻璃质感。 |
| 首页构成 | 左侧动态住宅科普／品牌展示，右侧账号登录；二者共处一个大矩形视觉容器，下方为柔和、精致的详情内容区。需按新极简风格重做，弃用此前插画式方案。 |
| 真实案例目的 | 以故事性吸引用户主动阅读，兼顾住宅科普与优缺点说明。 |
| 真实案例材料 | 基于**公开资料整理的内容样本**，并记录出处；以城市代表性居住方式为主，公众人物内容仅作合规补充。 |
| 中国地图用途 | **探索模式**，不承担房源搜索；展示城市地理、气候、生活方式与住宅样本。 |
| 中国地图覆盖 | 用户期望覆盖所有一、二线城市；建议把“新一线”纳入，具体城市名单须先固定年份和分级来源。 |
| 地图表现 | 分层、起伏、有探索感的现代极简地图；不以复杂真实三维地形为目标。 |
| 全球图鉴 | 以七大洲、国家／地区和代表性居住建筑为线索，突出地理、建筑与文化的关联。 |
| 与训练的联系 | 有相关性时跳转到风险知识或训练，不强制为每篇建筑文化文章配置题目。 |

## 04. 中国城市居住图鉴｜China Living Atlas

### 4.1 核心体验

**地图浏览 → 鼠标悬浮城市预览 → 点击展开城市信息 → 浏览住宅样本与故事 → 按需进入相关风险学习。**

地图承担“发现与认知”，不承担房价排序、实时挂牌、找房交易等任务。

### 4.2 页面与交互

1. **地图主画布**：轻量地形层次、城市节点、区域缩放与平移；地图主体保持简洁。
2. **悬浮城市卡**：城市名、地理标签、气候概览、居住关键词、示意图片。
3. **侧边城市详情**：城市简述、居住习惯、代表性住宅类型、精选故事、需要留意的居住问题。
4. **主题图层（后续）**：地理地形、气候与居住文化等信息视图。标注真实数据的图层必须使用可靠来源；装饰纹理不得冒充真实测量值。
5. **移动端交互**：用点按选中节点，底部信息面板或全屏详情替代纯 Hover 体验。

### 4.3 覆盖策略

覆盖目标为**所有符合选定分级口径的一线、新一线、二线城市**。产品需记录城市名单的**发布机构、分级年份、更新日期**；城市分级不应表述为官方行政等级。

建议分层交付：首批覆盖全部目标城市的**基础节点与基础档案**；再逐步完善高质量城市长文、住宅样本和摄影素材，避免因内容不足导致地图存在大片不可用区域。

## 05. 世界居住文化图鉴｜World Living Atlas

### 5.1 核心问题

**不同地区的人为什么以不同的方式建造、组织和使用居所？**

介绍建筑时，结合地理环境、气候、材料、历史、文化与日常生活，避免把建筑当成孤立的“景点”。

### 5.2 两条探索路径

- **主路径：按地理探索**——世界地图 → 大洲 → 国家 / 地区 → 代表性住宅 → 文章详情。
- **辅助路径：按居住环境探索**——寒冷多雪、热带湿润、干旱沙漠、山地高原、水乡海岸、现代都市等主题，对比不同地区的居住回应。

### 5.3 七大洲内容候选（不是已核实的正式样本库）

| 大洲 | 初步住宅内容示例 | 可讨论的主题 |
| --- | --- | --- |
| 亚洲 | 日本合掌造、中国窑洞、热带高脚屋 | 降雪、黄土、潮湿环境与材料 |
| 欧洲 | 冰岛草皮屋、荷兰运河住宅 | 保温、土地利用与水系城市 |
| 非洲 | 北非传统庭院住宅、西非土建筑 | 遮阳、通风、地方材料与家庭空间 |
| 北美洲 | 不同原住民社群传统住宅、现代郊区住宅 | 地区差异、历史与住居变化 |
| 南美洲 | 安第斯山地土坯住宅 | 海拔、材料与聚落环境 |
| 大洋洲 | 太平洋岛屿传统住宅、澳大利亚住宅 | 通风、热带环境与现代居住 |
| 南极洲 | 科学考察站 | 极端环境下的临时 / 长期科考居住；**不视作传统永久居民住宅文化** |

**编辑原则**：不把任何一种住宅形式泛化为“某国所有居民的住房”；必须标示具体地区、时代及其属于传统民居、历史建筑还是当代住宅。

## 06. 真实住宅故事｜Living Stories

### 6.1 内容目的

以真实、公开、可核实的居住样本提高探索兴趣，提供高品质摄影、简洁标题和可阅读的背景故事。以**城市代表性居住方式和典型建筑**为主，而不是名人房产八卦。

### 6.2 单篇内容模板（建议）

| 字段 | 展示内容 |
| --- | --- |
| 样本标题 | 建筑 / 住宅类型名，必要时注明所在城市和地区 |
| Hero 图片 | 已获授权或符合可用许可的真实摄影；图片说明与来源 |
| 一句话故事 | 这处住宅最值得了解的空间或文化特征 |
| 基本背景 | 所在地区、建造年代（如可核实）、类型、建筑特点 |
| 优点与不足 | 按真实使用条件解释，不把主观偏好表述为客观结论 |
| 地理与文化 | 气候、材料、建造方式、日常生活关联 |
| 风险 / 居住观察 | 与现代租住相关时补充，并清楚区分科普与法律建议 |
| 来源与更新时间 | 原始资料链接、来源名称、核验日期、图片授权状态 |

### 6.3 公众人物内容的边界

可谨慎采用**本人主动公开展示的住宅空间、正式公开的建筑项目或可靠报道中的居住设计故事**。不汇集或推测公众人物当前私人住址、具体小区单元、出入规律及未经验证的面积或房价。即使社交平台可以浏览，也不等于图片获得转载授权；百度 / 谷歌搜索结果不是版权许可。内容需独立核实并有编辑审核记录。

## 07. 首页与视觉设计体系

### 7.1 首页（当前最适合先改版的页面）

- 顶部：RentWise 品牌与简洁导航（首页 / 城市探索 / 世界居住文化 / 风险学习 / 登录）。
- 主体：**一个完整的大矩形视觉容器**，左侧为大幅高品质住宅摄影、可切换的居住科普焦点；右侧为登录表单与简短品牌说明。
- 下方：留白充分的精选居住故事、住宅类型介绍与探索入口，以杂志式排版代替大量重复卡片。
- 登录与注册沿用既有前端 API、JWT、Pinia 和路由逻辑；不要为了视觉改版修改认证契约。

### 7.2 统一风格

- **Apple-inspired Modern Minimalism**：暖白或极浅灰背景、近黑正文、低饱和点缀、现代系统无衬线字体。
- 大图优先，统一图片比例与裁切；依靠字体、留白、图片形成视觉层级。
- 仅在导航、图片控制层、悬浮面板等局部使用轻玻璃与模糊，不将整个页面玻璃化。
- 微交互原则上 150–250ms，大区域过渡可参考 250–400ms；避免夸张动画并尊重 `prefers-reduced-motion`。
- 提供 Hover、Focus、Selected、Loading、Empty、Error 等状态；可键盘使用、ESC 关闭抽屉、操作后焦点合理恢复。
- 桌面端地图与侧栏并排；移动端采取全屏地图 + 可展开底部面板；图片懒加载并支持失败占位。

### 7.3 设计系统优先

先制定颜色 / 字体 / 间距 / 圆角 / 运动规范，再建设导航、地图城市节点、预览卡、详情抽屉、图片画廊、来源提示、内容卡等可复用组件，最后逐页落地。

## 08. 与现有 RentWise 系统衔接

| 层次 | 当前 / 目标关系 |
| --- | --- |
| 现有业务 | v0.4 已有注册、登录、JWT、诊断、画像及学习相关功能；继续以稳定代码为基线。 |
| Explore 第一阶段 | 公开访问的静态内容页面 + 地图组件，不依赖新的业务微服务。 |
| 内容数据 | 建议先用审核过的结构化静态 JSON / TS 文件；图片素材需单独管理版权、体积和说明。 |
| 风险学习链接 | 按主题跳转到现有学习入口；需要登录时使用现有认证路由，并保留必要的返回上下文。 |
| 后续内容平台 | 在需要多人员编辑、发布和版本管理时，再设计内容管理接口与数据存储，现阶段不预设已实现。 |

**注意**：世界文化介绍的内容不必强制关联诊断或训练；关联应以信息是否相关为前提。真实房源搜索、实时价格和交易能力不属于此方案。

## 09. 迭代路线（提案，不是当前开发完成状态）

| 阶段 | 重点交付 | 验收关注点 |
| --- | --- | --- |
| P0 · 设计系统 | 视觉 Tokens、主要组件、桌面 / 手机页面框架 | 风格一致、无全局样式冲突、响应式正常 |
| P1 · 首页 | 左侧品牌 / 科普摄影 + 右侧登录 + 下方内容区 | 登录回归通过，图片加载与焦点交互稳定 |
| P2 · 中国地图基础 | 一、二线及选定新一线城市节点、城市预览、城市基础信息 | 城市可发现、悬浮 / 点击 / 手机点按可用 |
| P3 · 城市与住宅故事 | 城市详情、住宅案例、来源说明、主题链接 | 内容质量、引用核验、图片授权清晰 |
| P4 · 世界地图 | 七大洲入口、国家 / 地区节点、第一批代表性建筑文章 | 地图顺畅、内容准确、叙述不过度概括 |
| P5 · 体验完善 | 主题对比、内容编辑工作流、地图性能与无障碍 | 可维护性、加载表现、错误 / 空状态完整 |

当前课程微服务里程碑与 Explore 前端迭代**并行规划、分支隔离**；不为新视觉效果破坏已有 v0.4 的演示与课程验收。

## 10. 内容与工程风险清单

1. **信息真实性**：面积、价格、建筑年代、城市分级、气候等信息应说明来源和时间；未知则不展示或显著标记未核实。
2. **隐私与版权**：不以八卦为卖点披露私人住址；图片、文字和地图数据均需确认合理使用范围。
3. **地图合规与精度**：中国版图使用合规底图和审图信息；地形样式与真实海拔数据分层区分。
4. **文化准确性**：避免把族群、国家或大洲内多样居住文化简化为一个刻板形象。
5. **性能与访问性**：地图点位聚合、延迟加载、移动端触摸与弱网降级；不能靠动画表达唯一信息。
6. **范围蔓延**：先做文化探索与住宅图鉴，不混入尚未规划的找房、交易和实时房价服务。

## 11. 尚待讨论的决策

- **城市名单**：采用哪一份、哪一年的一线 / 新一线 / 二线分级名单？如何定义更新频率？
- **地图技术**：采用哪一套合规地图库 / 底图？地形表现是样式模拟还是引入真实高程数据？
- **首批内容**：首先深度制作哪些中国城市、哪些国家与建筑？文章的长度和深度如何控制？
- **内容来源**：如何建立图片许可检查、资料核验、来源标注和更新机制？
- **国际化**：世界图鉴第一期只提供中文，还是同时规划英文版？
- **账号体验**：公开 Explore 页面与登录用户状态如何在导航、收藏等未来功能中呈现？收藏功能尚未确认。
