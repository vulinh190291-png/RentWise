RentWise Living Picks｜居住灵感模块初步构想

版本：v0.1 · 创意记录稿
记录日期：2026-11-13
状态：产品探索 / 非正式 PRD / 尚未实现
归属建议：RentWise Explore 子栏目
关联文档：《RentWise Explore｜产品构想与 UI/UX 初步规划 v0.1》《RentWise UI/UX 设计规范与页面方案 v1.0》

01. 一句话定位

Living Picks 是一处可交互的居住灵感画廊：用户先看见一个真实、有氛围的房间，再通过图片中的可点击热点了解家具、灯具与装饰品，按需跳转到外部商品页面。

产品重心是空间欣赏、家居搭配和租住实用性，而不是交易。它不是 RentWise 自营商城，不承担购物车、支付、订单、售后或商品库存管理。

核心体验：发现空间 → 探索物件 → 理解搭配 → 查看外部商品 → 返回继续探索。

02. 与既有 RentWise 的关系

| 既有模块 | 角色 | Living Picks 的连接方式 |
| --- | --- | --- |
| China Living Atlas（中国城市居住图鉴） | 了解城市与住宅形式 | 从某类城市住宅进入适用的空间灵感专题 |
| World Living Atlas（世界居住文化图鉴） | 了解建筑与文化 | 关联具有相似设计语言的现代居家场景；不将商品直接等同于传统文化 |
| Living Stories（住宅故事） | 通过真实样本理解居住空间 | 从住宅样本延伸至可参考的空间搭配 |
| Risk Coach（租房风险实战教练） | 诊断、画像、专项训练 | 仅在适当处附上租房布置提醒；不强制导向答题 |

推荐归属：Explore → Living Picks / 居住灵感，作为独立公开内容栏目。首页可以使用一张精选空间图作为入口，不把“商城”放到 RentWise 主导航的核心位置。

03. 已确认的意图与未决议题

已明确的用户创意

以 Apple-inspired Modern Minimalism 为视觉主线，避免普通网格商品列表和过度特效。

一个页面展示多个不同光影与氛围的房间场景，以大幅图片吸引浏览。

每张场景图中包含不同的家居、家具或装饰品；用户点击图片中的商品位置即可了解该商品并进入购买相关页面。

希望形成与高品质品牌官网相近的精致、自然、连贯的体验。

当前建议、尚未正式确认

栏目英文名使用 Living Picks，中文名使用 居住灵感。

商品点击后先显示简洁的商品浮层或侧边卡片，再点击“前往商家”跳出站外；与用户“点击即可购买”的意图一致，但避免误触和突然离站。

第一版只做第三方商品链接，不开发自营交易系统。

内容重点偏向“租房友好、可移动、低破坏性、容易搬迁”的家居选择。

第一批精选 4–6 个空间场景，每个场景约 3–5 个可点击热点；数据只是建议的 MVP 规模。

04. 页面信息架构与视觉层级

4.1 页面入口 / 首屏

页面目标：让用户在几秒内理解，这是一处“看空间、找灵感”的场景画廊，而不是电商货架。

顶部保持与 Explore 一致的极简导航与品牌标识。

以宽幅真实空间摄影作为首屏视觉；标题简短，例如“从一个房间，找到喜欢的生活细节”。

简洁提示“点击图片中的圆点，探索房间里的物件”。

下方排列少量精选空间专题；避免首屏挤入筛选器、价格榜单或密集商品卡。

4.2 精选场景画廊

每个场景采用完整的宽幅图或高质量横向布局。建议图像保留自然光线、材料纹理和足够的留白；文字尽量置于图片外侧或有明确对比度的位置。支持场景切换，但不强制自动轮播。

第一批候选（不是正式内容库）：

| 场景 | 氛围定位 | 可探索物件示例 | RentWise 实用关联 |
| --- | --- | --- | --- |
| Solo Studio｜单人公寓 | 温暖自然光、简洁收纳 | 落地灯、边桌、置物架 | 小空间、可搬迁 |
| Work & Live｜居家工作区 | 明亮、功能主义 | 台灯、书桌、人体工学椅 | 空间复用、搬运成本 |
| Soft Living｜小客厅 | 低饱和中性色 | 沙发、地毯、茶几 | 尺寸匹配、地面保护 |
| Quiet Bedroom｜卧室 | 柔和暗光、安静 | 床头灯、窗帘、收纳柜 | 遮光、免打孔、噪声 |
| Balcony Corner｜阳台角落 | 植物、午后光线 | 椅子、花架、边几 | 承重、安全与物业约定 |
| Shared Home｜合租公共区 | 实用、多用途 | 可移动收纳、餐椅、照明 | 公共空间边界与协商 |

4.3 商品热点与详情卡

图片上的热点（Hotspot）是核心组件。悬停或键盘聚焦时给出简洁提示；点击后出现商品卡片，建议展示：

商品名称、品牌或来源、所属类别；

物件缩略图、极简介绍与“为什么适合这个空间”；

可选的参考价格（必须标记币种、来源与更新时间），信息未知则不显示；

租房友好标签：例如“可移动”“免打孔方案”“适合小户型”——需有事实依据；

查看商家页面：跳转已核实的第三方商品详情页。

不在图片上同时展示一大堆名称与价格。热点主要用于发现，详细内容延后显示。

4.4 场景说明与相关内容

图片下方用简短文字解释配色、光线、材质和布局思路；可附“这套布置适合什么样的租住空间”。在确有对应内容时，推荐中国城市图鉴、世界文化图鉴、住宅故事或租房注意事项。

05. 核心交互流程

进入 Living Picks
    ↓
浏览空间场景（摄影 + 极少文案）
    ↓
选中某个家具热点
    ↓
商品预览卡（物件介绍 / 价格与来源 / 租房友好提示）
    ├── 关闭卡片，继续探索房间
    └── 点击“前往商家” → 外部商品详情页

| 操作 / 状态 | 建议反馈 |
| --- | --- |
| Hover / Focus 热点 | 圆点轻微强化，出现名称标签；不使图片剧烈缩放 |
| 点击热点 | 原图位置不变；弹出局部卡片，选中热点有明显状态 |
| 切换商品热点 | 商品卡片原位更新，避免整页跳动 |
| 点击空白 / 关闭按钮 | 关闭卡片并返回原阅读位置 |
| 点击外部商品 | 明确标记“前往第三方网站”，建议新标签打开 |
| 移动端触摸 | 热点扩大触控区域；商品信息显示为底部抽屉 |
| 图片加载中 / 失败 | 骨架占位、压缩图回退、明确错误状态 |
| 动画受限 | 尊重 prefers-reduced-motion，关键信息始终可见 |

无障碍要求：所有热点都必须是可聚焦、可读名称的真实按钮；支持 Tab 依次移动、Enter/Space 打开、Esc 关闭，弹层具有适当的焦点管理，不能仅依赖 Hover。

06. UI/UX 规范：遵循既有 Apple-inspired 设计系统

视觉层级：空间图片第一、主题标题第二、商品信息第三；不让大量品牌 Logo 或价格抢走画面。

配色与材质：近黑文字、暖白 / 极浅灰背景、中性色按钮；玻璃质感只用在浮动控件或局部信息卡，不要全屏磨砂。

图片一致性：统一裁切规则；房间实景和商品图需匹配；如果画面是合成图，应如实标注，不得暗示商品真实存在于拍摄空间。

动效：热点 150–250ms 的轻量反馈，卡片 250–350ms 的淡入与位移；避免连续光效、自动旋转和夸张视差。

性能：Hero 采用响应式图片格式与尺寸；非首屏图片懒加载；限制同时解码的大图数量；热点使用百分比位置坐标。

适配：桌面以横向摄影和弹出卡为主；平板减少场景并排；手机使用单列图片、触控热点与底部商品信息面板。

07. 数据模型（建议；不是当前数据库表）

第一阶段可使用审核过的 TypeScript / JSON 静态数据，暂不引入新的 Java 微服务或商品数据同步。

| 数据对象 | 关键字段示意 | 说明 |
| --- | --- | --- |
| LivingScene | id, title, coverImage, imageCredit, description, tags, status | 单个房间场景 |
| SceneHotspot | id, sceneId, xPct, yPct, productId, label | 在图片中的相对位置（0–100%） |
| LivingProduct | id, name, brand, image, priceText, currency, merchantName, externalUrl, verifiedAt | 展示与外链信息 |
| SourceRecord | sourceName, sourceUrl, licenseStatus, checkedAt, notes | 图片、商品与内容资料来源 |

关键原则：图上每个热点必须对应一件能够明确识别的物品；未核实购买链接时不显示“购买”，可保留“查看设计说明”。

08. 内容、商业与合规边界

品牌定位：页面以居住审美和租房友好性为主，不以低价促销、冲动消费文案驱动用户。

图片授权：空间实拍、品牌商品图、官方宣传素材都应核实转载与商业展示许可；公开可见不等于允许复制。

真实关联：若使用 AI 合成或布景示意图，需说明是灵感示意；不能把视觉相似物直接宣称为画面中的真实可购买商品。

价格与库存：第三方商家价格、库存、促销会变化；无实时接口时不承诺实时性，不采用过期标价制造误导。

外链与用户信任：商品链接应人工检查目标域名，避免跳转到来路不明的页面；打开第三方网站时清楚提示离开 RentWise。

商业披露：若未来存在返佣、联盟链接、品牌赞助或广告合作，应在相关内容旁显著说明，而不是伪装成完全独立的编辑推荐。

租住安全：免打孔、安装、承重、用电、物业要求等提醒必须基于实际产品属性，不把一句“租房友好”当作通用安全保证。

隐私：第一版无需注册即可浏览，尽量不引入不必要的跨站跟踪脚本。

09. 与工程架构的衔接

当前 v0.4 已有 Vue 3 + TypeScript + Element Plus 前端、JWT 登录和既有学习业务；Living Picks 不需要先修改 Gateway、Nacos、User、Training、Profile、Plan 等现有服务。

建议的前端目标结构（拟新增）：

frontend/src/
├── views/explore/
│   └── LivingPicks.vue
├── components/living-picks/
│   ├── SceneGallery.vue
│   ├── ProductHotspot.vue
│   ├── ProductQuickView.vue
│   └── SceneStory.vue
├── data/living-picks/
│   ├── scenes.ts
│   └── products.ts
└── styles/
    └── (复用 RentWise 统一 Design Tokens)

若日后需要大量运营、动态价格、合作商家、推荐排序，再单独评估内容管理后端与第三方数据源。现阶段不新增专门的 Shopping Service，不开发支付闭环。

10. 分阶段开发路线与验收条件

| 阶段 | 交付范围 | 最小验收标准 |
| --- | --- | --- |
| P0 · 设计确认 | 视觉参考、场景示意、热点与商品卡状态稿 | 与 RentWise 设计系统一致；桌面/移动方案明确 |
| P1 · 静态 MVP | 4–6 个精选场景；每景 3–5 个热点；商品说明卡 | 点击正确、图片比例和热点坐标稳定、键盘可用 |
| P2 · 外部商品跳转 | 经过核验的真实商品来源与外链 | 每个外链指向准确商品；外链说明与错误回退完整 |
| P3 · Explore 内容关联 | 住宅图鉴、城市故事和 Living Picks 的内容跳转 | 阅读路径连贯；不依赖新增后端或虚构业务数据 |
| P4 · 运营与优化（按需） | 内容编辑流程、数据更新、性能与响应式优化 | 来源可追踪、链接可维护、移动端性能合格 |

测试重点：跨设备热点定位不偏移、同一图片不同裁切比例下可用；关闭商品卡后保持浏览位置；外链正确且安全；屏幕阅读器能读取商品名称；所有空状态、加载状态、图片失效和无网络情况得到处理。

11. 风险与取舍

| 方案 | 优点 | 主要代价 / 风险 | 当前建议 |
| --- | --- | --- | --- |
| 自营商城 | 完整交易链、强商业化 | 支付、订单、售后、合规与维护复杂 | 暂不做 |
| 场景热点 + 第三方链接 | 产品辨识度高、贴近已有 Explore | 图片版权、商品准确性、热点维护 | 优先 |
| 纯商品网格列表 | 开发简单、筛选方便 | 缺少空间探索特色，与定位不符 | 不作为主页体裁 |
| 大量 AI 生成场景 | 生产速度快、视觉统一 | 商品与画面难准确对应，易误导 | 仅作清晰标注的示意素材 |

12. 尚待确定的事项

栏目最终名称：Living Picks／居住灵感，还是 Shop the Space／空间好物？

第一批要先重点展示哪 4–6 个空间？希望偏“真实出租屋”还是“理想居家摄影”？

商品卡点击后是直接站外跳转，还是先预览再跳转？本文建议后者。

商品来源优先级：品牌官网、家居品牌官方商城、第三方平台，还是仅使用非商业设计参考？

是否允许未来出现带返佣的推荐链接？若允许，如何统一标注？

第一版是否允许示意价格？本文建议只展示有来源和核验日期的价格，不做伪实时数据。

Explore 首页露出多少 Living Picks 内容，如何避免压过中国城市图鉴、世界文化图鉴与 Risk Coach？

13. 本阶段结论

Living Picks 适合进入 RentWise，但应作为 Explore 旗下的“场景化居住灵感栏目”，不作为自营商城项目立项。

第一版最重要的不是商品数量，而是做到：一张照片足够吸引人、一个热点足够准确、一次跳转足够可信。先做可验证的小规模体验，再逐步扩展商品来源与编辑能力。
